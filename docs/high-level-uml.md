# High-Level UML

This diagram summarizes the main domain entities and system boundaries from the product and technical specifications. Markdown in the shared vault is authoritative; queues, transaction state, audit spools, and native agent stores remain outside it.

```mermaid
classDiagram
    direction LR

    class User {
        +String actorId
    }

    class AgentAdapter {
        <<interface>>
        +String agent
        +String version
        +String sessionId
        +String model
        +injectRootIndex()
        +publishLifecycleEvent()
    }
    class PiAdapter
    class HermesAdapter
    AgentAdapter <|.. PiAdapter
    AgentAdapter <|.. HermesAdapter

    class MemoryCLI {
        <<service>>
        +search()
        +show()
        +create()
        +update()
        +reconcile()
        +validate()
    }

    class Vault {
        <<store>>
        +String memoryPath
        +String sessionsPath
        +String systemPath
    }
    class RootIndex
    class ConceptIndex
    class ManagedLog

    class Concept {
        +String id
        +String title
        +String description
        +ConceptType type
        +Scope scope
        +String status
        +Markdown body
        +DateTime createdAt
        +DateTime generatedAt
    }
    class ConceptType {
        <<enumeration>>
        Project
        Person
        Preference
        Procedure
        Note
        Task
        Decision
        Reference
    }
    class Scope {
        <<enumeration>>
        work
        personal
        global
    }
    class Actor {
        +String id
        +String model
        +String sessionId
    }
    class Source {
        +String resource
        +String checkpointId
    }
    class Verification {
        +Actor actor
        +DateTime verifiedAt
        +String trustTier
    }

    class SessionSummary {
        +String agent
        +String sessionId
        +String status
        +String summaryPolicy
    }
    class Checkpoint {
        +String eventId
        +String trigger
        +Markdown nativeSummary
        +DateTime timestamp
    }
    class AccessEvent {
        +DateTime timestamp
        +String mode
        +String queryOrReason
        +String concepts
        +String model
    }

    class AuditSpool {
        <<state>>
        +String sessionEvents
    }
    class LifecycleDescriptor {
        <<state>>
        +String eventId
        +String trigger
        +String nativeReference
        +String state
    }
    class LifecycleWorker {
        <<oneshot service>>
        +claim()
        +materialize()
        +retry()
    }
    class SystemdActivation {
        <<activator>>
        +watchReady()
        +watchClaimed()
    }
    class NativeSessionStore {
        <<external>>
        +String piSessionReference
        +String hermesDatabaseReference
    }

    class Transaction {
        +String transactionId
        +Actor actor
        +String state
        +String commitHash
    }
    class MutationOperation {
        +String action
    }
    class GitRepository {
        <<history>>
    }

    class Obsidian
    class Syncthing

    User --> Obsidian : reads and edits
    User --> AgentAdapter : works through
    User --> MemoryCLI : administers and reconciles
    AgentAdapter --> MemoryCLI : search and mutate
    AgentAdapter --> LifecycleDescriptor : publishes
    AgentAdapter --> NativeSessionStore : references native state

    MemoryCLI --> Vault : managed reads and writes
    MemoryCLI --> AuditSpool : records retrieval
    MemoryCLI --> Transaction : executes mutations

    Vault "1" *-- "1" RootIndex
    Vault "1" *-- "1" ConceptIndex
    Vault "1" *-- "1" ManagedLog
    Vault "1" *-- "0..*" Concept
    Vault "1" *-- "0..*" SessionSummary

    Concept --> ConceptType
    Concept --> Scope
    Concept --> Actor : created/generated by
    Concept "1" o-- "0..*" Source
    Concept "1" o-- "0..*" Verification
    Source --> Checkpoint : may cite

    SessionSummary "1" *-- "0..*" Checkpoint
    SessionSummary "1" *-- "0..*" AccessEvent

    SystemdActivation --> LifecycleWorker : starts when queues are non-empty
    LifecycleWorker --> LifecycleDescriptor : drains claimed then ready
    LifecycleWorker --> NativeSessionStore : resolves bounded native summary
    LifecycleWorker --> AuditSpool : materializes access events
    LifecycleWorker --> SessionSummary : appends idempotent checkpoints

    Transaction "1" *-- "1..*" MutationOperation
    Transaction --> Vault : atomically replaces files
    Transaction --> GitRepository : stages owned paths and commits

    Obsidian --> Syncthing : synchronizes through
    Syncthing --> Vault : bidirectional Markdown replication
```
